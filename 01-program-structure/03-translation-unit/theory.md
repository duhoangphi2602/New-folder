# Translation Unit

## 1. Concept
A **translation unit** is the ultimate, final block of source code processed by the compiler. It is the result of taking a single source file (`.c` or `.cpp`) and running it through the preprocessor (which resolves all `#include` directives, expands macros, and evaluates `#ifdef` blocks).

```text
source.cpp
    + all #included headers (recursively copied in)
    - removed #ifdef blocks (code that was compiled out)
    + expanded macros
    ─────────────────────────
    = Translation Unit
```

## 2. Why
The C/C++ compilation model was designed in the 1970s. Compilers were severely memory-limited, so they could not load an entire project into RAM at once. 
The solution was to process **one translation unit at a time**. The compiler has zero knowledge of other `.cpp` files. It compiles each translation unit independently into an object file (`.o`). The linker then stitches all the `.o` files together.

## 3. Syntax (How Compilation Works)
There is no C++ syntax for a translation unit, but rather a conceptual flow:

```text
a.cpp ──preprocessor──→ Translation Unit A ──compiler──→ a.o
b.cpp ──preprocessor──→ Translation Unit B ──compiler──→ b.o
                                                          ↓
                                                       linker
                                                          ↓
                                                      executable
```

## 4. Example
*(See `examples/` for how to view a preprocessed translation unit)*

If `main.cpp` looks like this:
```cpp
#include "config.h"
int main() { return MAX_TEMP; }
```
And `config.h` looks like this:
```cpp
#define MAX_TEMP 100
```

The resulting Translation Unit generated by the preprocessor is:
```cpp
int main() { return 100; }
```
This is what the compiler actually sees.

## 5. Embedded usage (Internal Linkage)
In embedded projects, each driver (e.g., `uart.cpp`, `spi.cpp`) is its own translation unit.
A critical concept in embedded C is **Internal Linkage**. By marking a global variable or function as `static` in a `.c` file, you confine it exclusively to that translation unit.

```cpp
// uart.cpp
// This buffer cannot be seen or accessed by ANY other .cpp file in the project.
static uint8_t tx_buffer[256]; 
```
This is how encapsulation and data hiding are traditionally achieved in C.

## 6. Trade-offs

| Aspect | The Translation Unit Model | Modern Module Systems (e.g., Rust, Java) |
|--------|----------------------------|------------------------------------------|
| **Compile Times** | Slow. A single header included in 100 files is parsed 100 times. | Fast. Modules are parsed once. |
| **Simplicity** | Preprocessor is just text copy-paste. | Complex AST-level integration. |
| **Dependencies** | Hard to track automatically. | Built into the language. |

*(Note: C++20 introduced "Modules" to fix this, but they are practically non-existent in embedded C++ due to compiler limitations).*
