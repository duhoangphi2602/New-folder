/**
 * @file readelf_sim.txt
 * @brief Conceptual simulation of the `readelf` tool output on an embedded ELF file.
 */

==================================================
COMMAND: arm-none-eabi-readelf -h firmware.elf
(Display the ELF Header)
==================================================
ELF Header:
  Magic:   7f 45 4c 46 01 01 01 00 ... 
  Class:                             ELF32 (32-bit architecture)
  Data:                              2's complement, little endian
  Version:                           1 (current)
  OS/ABI:                            ARM EABI
  Machine:                           ARM
  Entry point address:               0x08000004  <-- Hardware will jump here on boot
  Start of program headers:          52 (bytes into file)
  Start of section headers:          24816 (bytes into file)

==================================================
COMMAND: arm-none-eabi-readelf -S firmware.elf
(Display the Section Headers)
==================================================
Section Headers:
  [Nr] Name              Type            Addr       Off    Size   ES Flg Lk Inf Al
  [ 1] .text             PROGBITS        08000000   000034 0021A4 00  AX  0   0  4
  [ 2] .rodata           PROGBITS        080021A4   0021D8 000100 00   A  0   0  4
  [ 3] .data             PROGBITS        20000000   0022D8 000050 00  WA  0   0  4
  [ 4] .bss              NOBITS          20000050   002328 000400 00  WA  0   0  4
  [ 5] .debug_info       PROGBITS        00000000   002328 01A044 00      0   0  1
  [ 6] .debug_line       PROGBITS        00000000   01C36C 008120 00      0   0  1

ANALYSIS:
- Notice how .text and .rodata are mapped to 0x08000000 (Flash memory).
- Notice how .data and .bss are mapped to 0x20000000 (RAM).
- Notice how .debug_info is massive (Size 0x1A044 = ~106 KB), but its Address is 0x00000000. It doesn't get loaded into microcontroller memory!
