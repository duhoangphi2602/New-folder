# The Linker Script

## 1. The Disconnect
The Compiler converts `int x = 5;` into an instruction to place `5` into the `.data` section.
But where physically is `.data`? The Compiler doesn't know. The Linker doesn't know either.
The Linker Script (`.ld` file) is a configuration text file that gives the Linker the physical address blueprint.

## 2. The `MEMORY` Block
This tells the Linker the absolute physical reality of the silicon chip (copied straight from the Datasheet).
```ld
MEMORY
{
  FLASH (rx) : ORIGIN = 0x08000000, LENGTH = 256K
  RAM (xrw)  : ORIGIN = 0x20000000, LENGTH = 64K
}
```
- `rx`: Read/Execute permissions (Code).
- `xrw`: Execute/Read/Write permissions (Variables).

## 3. The `SECTIONS` Block
This tells the Linker where to put the logical chunks (`.text`, `.data`) generated by the Compiler.
```ld
SECTIONS
{
  .text : {
    *(.text)   /* Take all .text from all .o files */
  } > FLASH    /* Put it in FLASH memory */

  .data : {
    *(.data)   /* Take all .data from all .o files */
  } > RAM AT > FLASH
}
```

## 4. VMA vs LMA
Look at the `.data` section above: `> RAM AT > FLASH`. 
This is the most critical concept in Embedded Systems.
- **VMA (Virtual Memory Address):** The address where the variable will live when the program is *running*. The `.data` section must have a VMA in **RAM** (so you can modify the variables). The compiler hardcodes all RAM addresses based on this.
- **LMA (Load Memory Address):** The address where the initial value of the variable is permanently stored when the power is *off*. The `.data` section must have an LMA in **FLASH** (e.g., the number `5` in `int x = 5;`).
On boot, the Startup Assembly Code physically copies the data from the LMA (Flash) into the VMA (RAM).

## 5. Exporting Symbols to C/C++
How does the Startup Assembly Code know where `.data` starts and ends? The Linker Script creates variables (Symbols) that can be accessed from C++ or Assembly!
```ld
_sdata = .; /* Create a symbol holding the current RAM address */
*(.data)
_edata = .; /* Create a symbol holding the end RAM address */
```
