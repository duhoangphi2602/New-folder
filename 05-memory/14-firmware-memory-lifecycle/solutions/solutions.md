# Solutions: Firmware Memory Lifecycle

## Solution 1: The Giant Array
**Answer:**
1. Declaring it inside `main()` places it on the **Stack**. Since the Stack is in RAM (and is usually very small), requesting 50KB will cause a massive **Stack Overflow**, crashing the system at runtime.
2. Declaring it globally places it in the **`.bss`** segment (since it is uninitialized, or `.data` if initialized). Both segments reside in RAM. Since the microcontroller only has 32KB of RAM, the compiler will throw a **RAM Overflow (Linker Error)**, and the build will fail.
3. You must add the **`const`** keyword. This moves the array into the **`.rodata`** segment, which resides permanently in the 128KB Flash memory, taking up 0 bytes of RAM and allowing the program to compile and run perfectly.

## Solution 2: System Architecture Review
**Answer:** 
1. The **Linker Script** defines the physical memory map. It places the `.isr_vector` section at the very beginning of Flash (`0x00000000`), and generates the memory addresses for the start/end of the `.data` and `.bss` RAM segments.
2. The **Vector Table** is a C-array placed inside that `.isr_vector` section. Its second element (Index 1) points to the memory address of the `Reset_Handler` function. When the hardware boots, it reads this table and jumps the CPU to that function.
3. The **Startup Code** contains the `Reset_Handler`. It uses the memory addresses generated by the Linker Script to physically copy the `.data` segment from Flash into RAM, and zeros out the `.bss` segment, finally preparing the environment and calling `main()`.
