# Interrupt Concept

## 1. Polling vs. Interrupts

Imagine you are waiting for a very important package to arrive at your front door.
- **Polling:** You open the front door, check if the package is there, close it, and repeat this every 5 seconds all day. You cannot read a book or watch TV. You are consumed by polling.
- **Interrupts:** You install a doorbell. You sit on the couch and watch TV. When the delivery driver presses the doorbell (Hardware Event), a loud noise sounds (Interrupt). You pause your TV show, go to the door to receive the package (ISR), and then resume your TV show exactly where you left off.

## 2. What is an ISR?
An **ISR (Interrupt Service Routine)**, also known as an Interrupt Handler, is a standard C/C++ function. 
However, you never explicitly call this function in your `main()` code. Instead, you register its memory address with the hardware CPU. When a specific hardware event occurs (e.g., a pin voltage goes from 0V to 3.3V), the CPU hardware automatically forces a Context Switch and jumps to this function.

## 3. The Execution Sequence
When an interrupt fires, the following happens at the hardware level (on ARM Cortex-M):
1. **The Trigger:** A hardware peripheral (Timer, UART, GPIO Pin) sets a flag in a specific hardware register indicating an event occurred.
2. **The Hardware Preemption:** The CPU finishes its current assembly instruction, but *refuses* to execute the next one.
3. **Context Save:** The CPU automatically pushes the current Program Counter (PC) and essential registers onto the active Stack.
4. **Vector Table Lookup:** The CPU looks up the memory address of your ISR function from the "Vector Table" (a hardcoded list of function pointers located at the very start of Flash memory).
5. **Execution:** The CPU jumps to your ISR function and executes it.
6. **Return:** When the ISR hits the `}` or a special assembly `BX LR` instruction, the CPU automatically pops the registers off the Stack and resumes the main program exactly where it was preempted.

## 5. Software vs Hardware Interrupts
- **Hardware Interrupt:** Generated by physical peripherals (UART data arrived, Button pressed, ADC conversion complete).
- **Software Interrupt (Trap/Exception):** Generated by the CPU itself when an error occurs (e.g., dividing by zero, Hard Fault memory violation, or the SysTick timer triggering the RTOS).
