# Interview Questions: Priorities & Preemption

## 1. Explain the concept of "Task Starvation" and how it is typically caused by a junior developer.
**Answer:** Task Starvation occurs when one or more low-priority tasks are permanently prevented from executing because a higher-priority task dominates the CPU. The golden rule of an RTOS is that the highest-priority Ready task always gets the CPU. Junior developers often assign a high priority to a task (like a math calculation or a `while` loop waiting for a hardware flag) but forget to include a Blocking API call (like `vTaskDelay` or `xSemaphoreTake`). Because the high-priority task never enters the Blocked state, it remains permanently in the Ready/Running state. The RTOS mathematically obeys its rules and gives that task 100% of the CPU forever, starving all lower-priority tasks and locking up the rest of the system.

## 2. Should you assign RTOS Task Priorities based on how "important" a feature is to the end-user?
**Answer:** No, assigning priorities based on human importance is a fundamental architecture flaw. Priorities should be assigned based on **Timing Deadlines**, commonly utilizing Rate Monotonic Scheduling (RMS). The task with the shortest, strictest deadline (e.g., reading a sensor every 2ms to prevent data loss) must be given the highest priority. A task that is incredibly important to the user (like sending a WiFi text message) but has a very loose deadline (it's fine if it takes 1 second or 3 seconds to send) should be assigned a lower priority. High-priority tasks must execute rapidly and immediately get out of the way.

## 3. What is "Preemption"? Can you disable it in FreeRTOS?
**Answer:** Preemption is the mechanism where the RTOS Scheduler forcefully interrupts a currently running task to give the CPU to a task that has a higher priority (which just woke up from a Blocked state). This guarantees Real-Time responsiveness, as the high-priority task does not have to wait for the low-priority task to voluntarily yield. 
Yes, you can disable it. In the `FreeRTOSConfig.h` file, you can set `configUSE_PREEMPTION` to `0`. This switches the OS into **Cooperative Scheduling** mode. In this mode, a high-priority task must wait patiently until the running task voluntarily calls a blocking function (like `vTaskDelay` or `taskYIELD()`) before it can take the CPU. Cooperative mode is rarely used in modern real-time systems as it destroys strict determinism.
