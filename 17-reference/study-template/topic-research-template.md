# Topic Research Template

Use this template when studying any topic in this repository. It forces you to go beyond "what" and cover "why," "when," and "how" — the level expected in an Embedded Software Engineer interview.

---

```markdown
# [Topic Name]

## 1. Concept
What is it? One-sentence definition.

## 2. Why does it exist?
What problem does it solve? What would happen without it?

## 3. How does it work?
Internal mechanism. (e.g., "the compiler inserts padding to satisfy alignment")

## 4. Syntax
Code syntax for C, C++, and C++17 (where applicable).

## 5. Basic Example (Desktop)
Simple, runnable code demonstrating the concept.

## 6. Embedded Example
Code showing how this concept applies to firmware development.

## 7. C Implementation
How this is done in pure C.

## 8. C++ Implementation
How this is done in C++ (class, RAII, template, etc.).

## 9. C++17 Approach
If C++17 offers an improvement (constexpr, optional, variant, etc.).

## 10. When to Use
Situations where this concept is the right choice.

## 11. When NOT to Use
Situations where this concept is inappropriate or dangerous.

## 12. Advantages
List of benefits.

## 13. Disadvantages / Limitations
List of downsides.

## 14. Comparison
Compare with alternatives (e.g., volatile vs atomic, bit-field vs bit-mask).

## 15. Memory / CPU / Performance Impact
How does this affect RAM, Flash, CPU cycles, latency?

## 16. Embedded-Specific Considerations
Platform constraints, toolchain behavior, ABI dependencies.

## 17. Common Mistakes
Errors that beginners (and even experienced developers) make.

## 18. Debugging Tips
How to identify issues related to this concept (e.g., GDB, static analysis).

## 19. Interview Questions
3-5 questions an interviewer might ask about this topic.

## 20. Related Concepts
Links to other topics in this repository.

## 21. Mini Exercise
A small coding exercise to test understanding.

## 22. Key Takeaways
3-5 bullet points summarizing the most important aspects.
```
